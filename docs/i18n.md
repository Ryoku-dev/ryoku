# Translation

Ryoku speaks 35 languages. Every surface a user reads goes through one catalog:
the shell and its bar, the Hub, the launcher, the apps, the wallpaper picker,
the greeter, the ISO installer and the `ryoku` CLI. This is how that works, and
what you have to do when you add a string.

## The rule

**A developer only ever writes English.** You wrap it where it is displayed,
and nothing else. No `.po` files, no message ids, no translator round trip in
your branch. After English copy changes, a maintainer runs the `i18n` workflow
by hand to extract the English, translate what is missing, and commit the
catalogs back.

```qml
text: I18n.tr("Power limit")
text: I18n.tr("Ready in %1 minutes").arg(n)
```

```go
title := i18n.T("Pick a disk")
line  := i18n.Tf("formatting %s as btrfs", dev)
```

```bash
log 'locale: %s' "$RYOKU_LOCALE"
die 'carve target %s is not a block device.' "$part"
```

The English source string **is** the key. An untranslated string returns itself,
so a missing translation shows English rather than a blank or a `?TR_ID?`, and
adding a language is purely additive: nothing can break by being untranslated.

## The layout

Everything lives under `ryoku/i18n/`:

|Path|What it is|
|---|---|
|`langs.json`|The one language table. Code, English name, native name, Google target code, text direction, glibc locale.|
|`catalog/<code>.json`|The generated catalog for one language. Machine-written; never hand-edit.|
|`catalog/overrides/<code>.json`|Human fixes. Always wins over the generated string, and the generator never overwrites it.|
|`i18n.go`, `langs.go`|The Go runtime. Module `ryoku-i18n`.|
|`catalog/catalog.go`|The catalogs compiled in, for a binary with no filesystem to read.|
|`tools/sync.py`|extract, sync, check, cost, llm. Ships as `/usr/bin/ryoku-i18n`.|
|`tools/wrap.py`|An AST wrapper that finds displayed literals in QML and wraps them.|
|`tools/install.sh`|Puts the catalog where a dev checkout looks for it.|

On an installed system the catalog is at **`/usr/share/ryoku/i18n/`**, laid there
once by `ryoku-desktop`. Three runtimes read that one directory:

- **QML** through `ryoku/ui/Singletons/I18n.qml`, which watches the file and
  retranslates every open surface live when the language changes.
- **Go** through `ryoku/i18n/i18n.go`, used by the `ryoku` CLI.
- **Shell** through `installation/backend/lib/i18n.sh`, used by the installer.

Two binaries cannot read that directory, because they run where it does not
exist: the ISO's installer TUI and the standalone shell installer that lands on
a stranger's distro. Both import `ryoku-i18n/catalog`, which compiles the
catalogs into the binary. Nothing else imports it, so the catalogs stay out of
every `vendor/` tree.

## Adding a language

Add a row to `ryoku/i18n/langs.json`. That is the whole change. The Hub's
picker, the installer's language list, `sync.py`'s target set, the Go runtime's
table and the RTL decision all read that file, so there is no second list to
keep in step.

After adding the row, run the `i18n` workflow by hand. It translates the new
language and commits `catalog/<code>.json`.

## Adding a string

Wrap it in English at the display site and push. After copy changes land, run
the `i18n` workflow from the Actions tab or with
`gh workflow run i18n.yml --ref unstable-dev`. It:

1. `sync.py extract` walks the tree for wrapped strings and writes `catalog/en.json`
2. `sync.py sync --engine llm` translates, per language, **only the strings that
   language is missing** (an override or an existing translation is kept)
3. `sync.py check` warns about translations far longer than their English source,
   which is what makes a settings row overflow
4. `sync.py cost` prints what the pass cost
5. commits `ryoku/i18n/catalog`

If the translation provider is out of credits or otherwise unavailable,
`sync.py sync` exits with code 3 before writing the current language. Run the
workflow again when the provider is available.

A normal change translates a handful of strings, not the file.

### What gets extracted

- QML: `I18n.tr("...")`, `Translation.tr("...")` and `qsTr("...")`
- Catalogue items: Subshells and bar styles from the store share Ryoku's catalogue
  and ship no catalogue files of their own. Pass a checkout of the catalogue repo
  with `sync.py extract --store ../ryostore-revamped`, or set `RYOKU_STORE_SRC` to
  it, and extraction also walks every `subshells/*/qml` and `barstyles/*/qml`
  there, including model fields whose values are translated where they are
  rendered
- Hub schema `.js`: `label`, `desc`, `group`, `tab`, and string `opts`
- Hub pages: `pTitle` / `pEyebrow` / `pBlurb`, and `{key, label}` model tables
- Go: `i18n.T("...")` / `i18n.Tf("...")`
- The shortcut catalogue: `Category`, `Label` and `Hint` in `ryoku/wm/binds.go`,
  and each compositor's reason for a bind it cannot honour, which Kit and the
  Hub translate where they are rendered
- Shell: `t "..."` / `tf "..."`, including through `log` and `die`

### What is never extracted

Icon glyph names, config keys, paths, URLs, font families, units (`GB`, `Hz`,
`px`), key engravings (`Super`, `Shift`), brand kana, single characters, and
anything with no ASCII letter. A "translated" `GB` is wrong in every locale, and
localized digits in a numeric readout are worse than no translation at all.

Weekday and month names are **not** catalog strings. Use
`Qt.locale().standaloneDayName(i, Locale.NarrowFormat)`: a Polish week is
`P W S C P S N`, which no translation of the letter `M` could produce.

## Placeholders

Keep a sentence whole. A translator needs the whole clause to put the words in
the right order, and several languages cannot use English word order at all.

```qml
// wrong: three fragments, word order frozen to English
text: I18n.tr("Ready in ") + n + I18n.tr(" minutes")
// right
text: I18n.tr("Ready in %1 minutes").arg(n)
```

QML uses `%1`..`%9` with `.arg()`; Go and the installer's shell use `printf`
verbs. Either way the placeholders travel with the translation, so a target
language can reorder them (`%[2]s` in Go, `%2$s` in shell). `sync.py` compares
the placeholder multiset of every translation against its source and **drops**
any translation that lost, gained or translated one, shipping English for that
string instead. A mangled `%s` can never reach a release.

## Right to left

Arabic, Hebrew and Persian are in the table with `"dir": "rtl"`. `I18n.rtl` and
`I18n.dir` expose that, and a surface roots its layout on it:

```qml
LayoutMirroring.enabled: I18n.rtl
LayoutMirroring.childrenInherit: true
```

Qt then mirrors anchors, rows, layouts and text alignment for everything below,
so the mirroring is set once per top-level surface rather than per component.
Text alignment mirrors on its own: `Text` reports an `effectiveHorizontalAlignment`
that follows the layout direction, and Qt's bidi algorithm already lays out
Arabic runs correctly inside an unmirrored element.

Glyph coverage is already installed: `noto-fonts` carries Arabic, Hebrew,
Devanagari, Bengali, Tamil, Telugu, Malayalam, Thai, Greek and Cyrillic, and
`noto-fonts-cjk` carries Chinese, Japanese and Korean. Both are hard
dependencies of `ryoku-desktop`. Fontconfig substitutes per glyph, so a Latin UI
font with no Arabic in it still renders Arabic.

## Choosing a language

`shell.json`'s `language` key. `Auto` follows the system locale. The Hub's
Global page picks it from `langs.json`, showing each language under its own
name, and changing it retranslates every open surface at once with no relogin.

The lookup order, everywhere:

1. `~/.config/ryoku/i18n/<code>.json` - the user overlay, and where
   `ryoku-i18n llm <code>` writes a locally generated language
2. `/usr/share/ryoku/i18n/<code>.json` - what Ryoku ships
3. the English source string

Resolution order for *which* language, everywhere:

1. an explicit request (the Hub's setting, the installer's step)
2. `RYOKU_LANG` - how the installer TUI tells its shell backend
3. `shell.json`'s `language`
4. `LC_ALL` / `LC_MESSAGES` / `LANG`, with a regional tag falling back to its
   base language, so `de_AT` reads `de.json` rather than dropping to English

The greeter runs before any session exists and cannot read `shell.json`, so it
lands on step 4 and follows the system locale.

## Working on it locally

```bash
ryoku/i18n/tools/install.sh                          # catalog -> ~/.local/share/ryoku/i18n
python3 ryoku/i18n/tools/sync.py extract             # rebuild catalog/en.json
python3 ryoku/i18n/tools/sync.py extract --store ../ryostore-revamped   # plus catalogue items
python3 ryoku/i18n/tools/sync.py langs               # the codes this repo ships
python3 ryoku/i18n/tools/sync.py cost                # price the next full pass
python3 ryoku/i18n/tools/sync.py check               # translations that will overflow the UI
python3 ryoku/i18n/tools/sync.py sync --engine llm pl # one language, needs a key
/tmp/venv/bin/python ryoku/i18n/tools/wrap.py --dry-run <files...>   # what is still unwrapped
```

`wrap.py` needs `tree_sitter` and `tree_sitter_qmljs`; it parses QML rather than
regexing it, so it never wraps a comparison literal or an icon name.

`RYOKU_I18N_DIR` overrides the catalog directory for every runtime at once,
which is how the tests and a dev shell point at a checkout.

### A better translation than the machine's

Two ways, and both survive an update:

- **Ship the fix**: put it in `catalog/overrides/<code>.json`. The generator
  never overwrites an override, and every user gets it.
- **Fix your own box**: `ryoku-i18n llm <code>` writes
  `~/.config/ryoku/i18n/<code>.json` with your own API key and model, which
  layers over the shipped catalog. Ryoku Settings > Global > Language has the
  button.

## Cost

`sync.py cost` prices the next pass against the configured model, reading the
real catalog: how many strings each language is missing, the input and output
tokens that implies, and the dollars. `--force` prices a full re-translate,
`--model=` prices a different model, and `--in=`/`--out=` price one the table
does not know.

The model is a repository variable (`RYOKU_I18N_MODEL`), not a code change, so
switching is a settings edit and `cost` tells you what it buys.
